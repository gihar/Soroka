# ADR-0007: Пресет модели — полный адрес провайдера

Дата: 2026-08-06. Статус: принято.

## Контекст

До сих пор все пресеты жили на одном OpenRouter с одним ключом, поэтому
`OPENAI_API_KEY`/`OPENAI_BASE_URL` из `.env` были фактической точкой правды, а
пресет менял только модель ЭТАПА 2. Два вызова из трёх — сопоставление спикеров
(`speaker_mapping_service`) и ЭТАП 1 анализа (`protocol_generator`) — ходили
мимо пресета: в `default_client` с глобальными `SPEAKER_MAPPING_MODEL` и
`ANALYSIS_STAGE_MODEL`. Пока провайдер один, это незаметно.

Подписка Qwen (Token Plan) сделала склейку видимой. У неё отдельный хост
(`token-plan.<region>.maas.aliyuncs.com/compatible-mode/v1`) и отдельный класс
ключа (`sk-sp-…`), несовместимый ни с общим DashScope, ни с OpenRouter. Пресет,
меняющий только одну модель из трёх, физически не может переключить бота на
другого провайдера.

## Проверено на живом эндпоинте (2026-08-06)

Замеры определили несколько решений ниже и в коде не видны:

- `qwen3.7-plus` — строгие схемы **применяются**: на схеме с невозможными
  ключами модель вернула ровно их, проигнорировав содержательный промпт.
- `qwen3.6-flash` — HTTP 200, валидный JSON, **схема молча выброшена**: вернулись
  собственные ключи модели. Отказ бесшумный, по коду ответа неотличим от успеха.
- `qwen3.7-max`, `qwen3.8-max` — не уложились в 110 с, при `LLM_TIMEOUT_SECONDS`
  = 30 непригодны.
- `enable_thinking` у `plus` включён по умолчанию: 19.9 с и 1019 выходных
  токенов против 4.4 с и 116 при выключенном (промпт 3.1k токенов).

## Решение

1. **Пресет — полный адрес провайдера.** Ключ, base_url, модели всех трёх
   вызовов, `extra_body`, `extra_headers`. Смена пресета переносит весь LLM-путь
   целиком; провайдер у трёх шагов всегда один.

2. **Дешёвые шаги — необязательные поля пресета** (`analysis_model`,
   `mapping_model`) с фолбэком на основную модель. Глобальные
   `SPEAKER_MAPPING_MODEL`/`ANALYSIS_STAGE_MODEL` перестают быть точкой правды:
   имя модели бессмысленно вне своего провайдера. У Qwen-пресета оба поля пусты —
   все три шага идут на `qwen3.7-plus`, потому что все три ходят со строгими
   схемами, а единственная дешёвая модель эндпоинта их игнорирует.

3. **`api_key` появляется в `OPENAI_MODELS`, `OPENAI_API_KEY` перестаёт быть
   обязательным.** Пресет целиком объявляется в `.env` и воспроизводится при
   переезде; `is_available()` смотрит на наличие пресетов, а не на глобальный
   ключ, иначе чисто-Qwen деплой невозможен. `upsert` бережёт ключ через
   `COALESCE`, поэтому пересинк из конфига не затирает заданный через
   `/add_model`.

4. **Параметры провайдера — через `extra_body`/`extra_headers` пресета.** Для
   Qwen обязателен `enable_thinking: false` — не оптимизация, а условие
   попадания в таймаут. Зеркально: `HTTP-Referer`/`X-Title` — атрибуция
   OpenRouter, она уезжает из глобальных настроек в OpenRouter-пресеты.
   Генератор перестаёт знать имена провайдеров.

5. **Квота подписки — событие, отдельное от кредитов.** Исчерпание опознаётся
   не только по 402: отдельный класс ошибки и отдельный текст алерта («смените
   активный пресет»), потому что пополнение баланса здесь не помогает. Автоматической
   подмены модели посреди протокола нет; при глобальном переключении на Qwen
   квотная стена возвращает активный пресет на OpenRouter и уведомляет админа.

6. **Поддержка строгих схем — свойство модели, проверяемое зондом.** Команда
   `/check_model` гоняет схему с невозможными ключами и отвечает «применяется /
   игнорируется». Дополнительно валидатор сверяет ответ с ключами брифа и громко
   сообщает о расхождении. Ремонтного ретрая нет: при рабочих схемах ему негде
   сработать, а неисполняемая ветка не проверяется в бою.

7. **Обкатка — через перегенерацию, и только для админов.** Перегенерация из
   истории получает выбор модели по образцу выбора шаблона: тот же вход, другой
   провайдер, сравнение бок о бок без трогания глобального пресета. Видна только
   администратору — модель остаётся глобальным параметром, а квота подписки не
   расходуется по прихоти пользователей.

## Отвергнутые альтернативы

- **Автопроба «послать схему, при 400 откатиться на json_object».** `qwen3.6-flash`
  отвечает 200 и выбрасывает схему молча — проба уверенно заключила бы, что всё
  работает. Против бесшумного отказа диагностика по коду ответа бессильна.
- **Оставить пресету только модель генерации.** Ноль изменений в архитектуре, но
  тогда одновременно нужны два рабочих провайдера, и «переехать на Qwen» не
  получается в принципе.
- **Автофолбэк на запасной пресет внутри одного прогона.** Протокол оказался бы
  склеен двумя моделями, а расход подписки — незаметным.
- **Жёсткая привязка параметров к `base_url` в коде генератора.** Знание о
  провайдерах вернулось бы в глубокий модуль, откуда его вычищали.
- **Отдельная переменная `QWEN_API_KEY`.** Вводит «именованного провайдера» третьей
  сущностью там, где хватает пресета.
- **Флаг `admin_only` как обкаточная фаза.** Единственный его читатель,
  `get_enabled_for_user`, не вызывается ниоткуда, а активный пресет глобальный:
  пометка не дала бы обкатки, переключение сразу увело бы на Qwen всех.

## Считаемые последствия

- Пресет становится обязанным быть полным: пресет без ключа работает, только
  если задан глобальный `OPENAI_API_KEY`. Смешанная конфигурация («часть
  пресетов наследует общий ключ») остаётся законной ради обратной совместимости,
  но перестаёт быть рекомендуемой.
- Единый rate-limiter `openai_api` (60/мин) остаётся общим на всех провайдеров.
  При двух активных адресах это консервативно, но неточно.
- `LLM_TIMEOUT_SECONDS` = 30 становится значимым ограничением выбора модели:
  оно исключает `max`-модели Qwen и требует выключенного thinking у `plus`.
